# panasonic-rd-bus

Local Home Assistant control for Panasonic **residential ducted** air conditioners that only
have a 2-wire wired controller (terminals **R1/R2**, CZ-RD514C family). These units have no
CN-CNT port, so the usual Panasonic ESPHome projects don't apply. An ESP32 joins the R1/R2
bus as a **second wall controller**: it reads the unit's real state and sends the same
commands the wall controller does. No cloud, no IR, no button pressing.

**Status:** working on a Panasonic **W18BD3P** with a **CZ-RD514C** controller (Spain,
2026-11). Power, mode, fan, setpoint and the filter warning work from Home Assistant, and
changes made at the wall controller show up in Home Assistant too. It is tested on **one
unit**; if you try it on another, please open an issue with your model and a capture.

> Have a PACi (commercial) unit with a CZ-RTC controller instead? Use
> [rndm2/esphome_panasonic_paci](https://github.com/rndm2/esphome_panasonic_paci) with a
> CZ-CAPWFC1 bridge. That is a different protocol.

The story of how it was decoded: [docs/writeup.md](docs/writeup.md).

## How the bus works (short version)

- 2 wires, ~15 V DC. A device talks by pulling the line down with a **~19 kHz carrier**
  for each 0-bit; silence is a 1-bit. **2 ms per bit, 8E1** (~495 baud).
- The bus polls `80 81 90…9F` every 154.6 ms. The wall controller answers poll `80`;
  poll `81` (a second controller) is free, so the ESP32 answers there, 44 ms after it.
- Frames are `E3|E1 LEN payload CS` with `sum & 0x7F == 0`. `E3` = wall controller,
  `E1` = indoor unit.
- Registers: `60` power, `61` mode, `62` fan, `64` setpoint (°C = value + 16), `66` filter.

Full details, timings and unknowns: [docs/protocol.md](docs/protocol.md).

## Hardware

Three ways to build the interface. All share the same proven circuit
([docs/hardware.md](docs/hardware.md)): one NPN transistor + 10k/680 Ω divider to receive,
one NPN transistor + 220 Ω to transmit.

| Option | What | State |
| --- | --- | --- |
| Breadboard | ESP32 DevKit, 2 × 2N2222, 6 resistors | working (this is what runs today) |
| [PCB v1](hardware/pcb/) | 60 × 46 mm, ESP32-C3 module, USB-C powered, factory-assembled at JLCPCB | ordered, boards on the way |
| [PCB v2](hardware/pcb_v2/) | same, but powered from the AC bus itself (~19 mA, current-limited) | design, not built yet |
| [PCB v3](hardware/pcb_v3/) | same as v1, but **isolated**: optocouplers + isolated DC-DC, the ESP32 never shares a wire with the bus | design, not built yet |

The board files are generated by a Python script against KiCad 10's API (`build_pcb.py`),
checked with KiCad's DRC, and come with JLCPCB-ready Gerber/BOM/CPL files.

### Quick start (breadboard)

1. Build the circuit in [docs/hardware.md](docs/hardware.md) and read its safety notes first.
2. Create `esphome/secrets.yaml` with `wifi_ssid`, `wifi_password`, `api_key`,
   `ota_password` and `ap_password`.
3. Flash:
   ```bash
   cd esphome
   esphome run panasonic-ac.yaml
   ```
4. Add the device in Home Assistant (Settings → Devices → ESPHome). You get a climate
   entity, a "Filter needs cleaning" sensor and a "Reset filter warning" button.

The register values in the YAML are the ones confirmed on a W18BD3P. Another model may
differ: map yours with the sniffer first ([docs/test-plan.md](docs/test-plan.md)).

## Safety and disclaimer

- **Switch the AC off at the breaker** before touching its wiring. On many indoor units the
  R1/R2 terminals sit next to mains terminals.
- The simple circuit is **not isolated**: the ESP32's ground is bus −. Find which wire is +
  with a multimeter first. Never let bus voltage (15 V) reach a GPIO directly; it will
  destroy the pin.
- This is an independent hobby project, not affiliated with or endorsed by Panasonic. Adding
  a device to your AC's control bus may affect your warranty. You do this at your own risk.
